# 06 · 经典真题总览

> E5 备考不需要刷 50 道题。**把 8–10 道题打到「能深挖一层」的程度，比刷 30 道「都画过图」强得多。**

## 1. 题目分级（对齐 Hello Interview 难度体系）

### Easy（必须无瑕疵）
- 短链服务（[Q1](questions/01-url-shortener.md)）——考 ID 生成、缓存、重定向
- 限流器（[Q2](questions/02-rate-limiter.md)）——考算法深挖 + 分布式时钟
- Top-K / Heavy Hitters（[Q3](questions/03-top-k-heavy-hitters.md)）——考流式算法 + 精确性 trade-off

### Medium（E5 核心火力区）
- 聊天系统（[Q4](questions/04-chat-system.md)）
- News Feed（[Q5](questions/05-news-feed.md)）
- 分布式消息队列（[Q6](questions/06-distributed-message-queue.md)）
- 票务预订（[Q7](questions/07-ticket-booking.md)）——Hello Interview 标注的 E5 高频
- 广告点击聚合（[Q8](questions/08-ad-click-aggregator.md)）——E5 高频，流处理全家桶

### Hard（有余力再碰）
- Google Drive / Dropbox（文件存储 + 分块 + 同步）
- YouTube / Netflix（视频转码管道 + CDN）
- Google Maps（分块索引 + 路径规划）
- 搜索引擎（爬取 → 索引 → 排序）
- Uber（地理位置索引 GeoHash + 匹配调度）

## 2. 题目背后的「母题」

几乎所有题都是这 5 个母题的变体，认出母题就认出了考官的采分点：

| 母题 | 核心矛盾 | 覆盖题目 |
|------|---------|---------|
| **读多写少 + 缓存** | 命中率 vs 一致性 | 短链、Feed、个人主页 |
| **写多 + 削峰** | 吞吐 vs 延迟 vs 丢数据 | 日志、点击聚合、消息队列 |
| **状态同步（长连接）** | 连接规模 vs 推送延迟 | 聊天、协作编辑、游戏 |
| **并发资源竞争** | 一致性 vs 可用性 | 票务、秒杀、转账 |
| **Fan-out 写放大** | 写时扩散 vs 读时聚合 | Feed、通知、社交图谱 |

**练习后期专门练「母题迁移」**：拿到没见过的题，先花 30 秒归类母题，直接套用深挖储备。

## 3. 每道题的练习流程（不要反过来！）

```
1. 盲做（45 min，计时、白板、录像）     ← 最重要，禁止先看解析
2. 对照解析（30 min），标记三类差距：
   □ 流程性差距（忘了问 X / 时间失控）
   □ 知识性差距（不懂某个组件的原理）
   □ 深度差距（没挖到 trade-off 层）
3. 写一页 personal cheat sheet（决策清单，不是知识摘要）
4. 3 天后重做同题（不看 cheat sheet），对比录像
5. 一周后讲给朋友听 15 分钟版
```

## 4. 深挖储备：每题必备的「深挖三选一」

面试深挖阶段（Phase 5）基本是面试官从这三个方向选一个，提前备好：

- **数据层**：存储选型 / 分片键 / 索引 / 一致性
- **故障层**：单点 / 过载 / 部分失效（脑裂、网络分区）
- **演化层**：流量 ×10 / ×100 之后架构怎么改

## 5. 本 repo 的题目解析结构

每道题按统一结构（和 [03 表达框架](03-delivery-framework.md) 完全对齐）：

1. **题目原文**（面试官那张模糊的卡片）
2. **澄清问题清单**（你应该问什么、每个问题的意图）
3. **估算演示**（数字 → 结论）
4. **高层设计**（组件图 ASCII + 数据流）
5. **数据模型**
6. **深挖 1/2/3**（本题最常见的三个深挖方向及 E5 水平的答案）
7. **红牌答案**（哪些答案直接暴露不是 E5）
8. **一分钟电梯版**（mock 前的复习卡）
